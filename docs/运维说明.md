代码来源：GitHub `yoorme/squad-signup-latest`（push 到 main 触发 Actions 构建并更新 `latest` Release）。

## 日常更新流程

```bash
cd /opt/squad-signup
bash update.sh             # 停主站 → 下载产物 → 迁移主库 → 重启 3000
bash update-instances.sh   # 各实例：迁移实例库 + 重启实例服务（YFD 等）
```

> 注意：只跑 update.sh 的话 YFD 会继续运行旧代码且库结构不迁移——**务必跟跑 update-instances.sh**。

## 关键配置（各 .env）

| 变量 | 说明 |
|---|---|
| `PORT` | 服务端口 |
| `AUTH_COOKIE_NAME` | 会话 Cookie 名，多实例必须互不相同（防互相踢下线） |
| `TRUST_PROXY` | 无反代时必须为 `false`（防伪造头绕过登录限流）；以后挂 Nginx 改 `true` |
| `CRON_SECRET` | 临近提醒定时扫描密钥（systemd timer 使用） |
| `JPUSH_APPKEY` / `JPUSH_MASTER_SECRET` | 极光推送，未配置则推送静默关闭 |
| `TEAM_PREFIX` | 仅首装 seed 使用；日常改前缀请在网站「战队管理」操作 |

## 定时任务

- **临近提醒扫描**：`squad-notify.timer` / `squad-notify-shuishangyue.timer` 每分钟 curl
  `/api/notifications/tick`（带 CRON_SECRET），扫描 24h 内开赛的报名者并推送提醒，PushLog 去重。
- **数据库备份**：`/etc/cron.d/squad-db-backup` 每日 03:17/03:18 用 pg_dump 备份两库到
  `/opt/backups/squad/*.sql.gz`，保留 7 天。

## 会话 Cookie 说明

多实例共用同一 IP，浏览器 Cookie 不区分端口。`AUTH_COOKIE_NAME` 已按实例区分
（`squad_signup_session` / `shuishangyue_session`），此后 MMR 与 YFD 可在同一浏览器同时登录。
（该变更使所有旧会话失效一次，用户需重新登录。）

docker exec 1Panel-postgresql-EplD psql -U user_YiXQ7r -d squad_signup -c '\dt'  # 库结构
